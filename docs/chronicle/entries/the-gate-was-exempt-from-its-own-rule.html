The gate wrote its evidence into the cache it forbids everyone else to touch

PRC

A hook rule denies every writer access to the engine's import cache, because rebuilding it blanks the level for whoever is playing out of the same tree. The gate wrote three of its own scratch files straight into that directory — it was the one writer exempt from the rule it enforces, by being the thing that wrote the rule. The paths were also fixed rather than per-run, so two concurrent gate runs deleted each other's evidence while the accessibility analyser was still reading it. Fixing it also answered the question PRC-15 calls the single biggest reason worktrees are not free here, and the answer turned out to be that they are.

Three rendering checks each wrote to a fixed path inside .godot/, the engine's import cache: a game frame, a menu frame, and four accessibility captures with their JSON reports.

Two things wrong with that, and the second one is funnier

Fixed paths mean two concurrent gate runs delete each other's evidence. The accessibility analyser samples its background colours *out of those PNGs*, so it could read a frame another process had already unlinked. “Two agents ran the gate at once” had no defence at all — and that has to be true before parallel agents are safe at all.

And .godot/ is the directory the owner's running game reads from. guard.py's rule_godot_write denies every writer access to it, for exactly the reason LF-075 records: rebuilding or moving that cache pulls every texture out from under a live session, the menu still draws, the level comes up blank, and it reads precisely like a code regression. It cost a full diagnosis pass once.

So the gate was the one writer exempt from the rule it enforces, by being the thing that wrote the rule. Scratch files now go to .cache/gate/, alongside the leases and the parity digests.

One deliberate deviation from the spec

PRC-15 asks for the temp directory to be removed in a finally. It is not, and that is on purpose.

The old code unlinked its frame after the assertions passed, and returned early on failure — so a failing rendering check left its frame on disk to be looked at. That is the entire value of a rendering check that failed. A blanket finally: rmtree would have been tidier and would have destroyed the evidence every time it mattered. Cleanup happens on success only; a failure keeps the directory, and the failure message now says where it is.

Both paths were driven directly rather than reasoned about — a synthetic passing check leaves nothing behind, a synthetic failing one keeps its file and reports the path, with the pid in the directory name so a hard-killed run leaves a trail rather than a mystery.

And the question that had been sitting under all of this

PRC-15 calls one of its tasks *“the single biggest reason worktrees are not free here”*: does each worktree need its own import cache, and can it have one? Worktree isolation is the top item on the process backlog, so this is the number that gates it.

It gets one automatically. Godot has no cache-location flag — checked against --help on the real binary, where the only relevant flags are --path and --import — and --path <dir> implies the cache inside that directory. Isolation is by construction rather than by configuration, which removes the whole LF-075 class of risk from worktree agents instead of mitigating it. The residual cost is one import and about 128 MB.

A requirement withdrawn

The same spec requires worktrees to live outside the main checkout, citing LF-051 — six false nomenclature hits off an agent worktree under .claude/. But LF-051 was fixed differently and better: the gate enumerates with git ls-files, so an untracked worktree is *structurally* invisible to it, and .claude/worktrees/ is gitignored besides. Both verified directly.

So the requirement's reason is gone, and the Agent tool's native worktree isolation — which puts them exactly there — is fine. Withdrawn in place, with the reasoning recorded, because a spec is not append-only and a stale requirement is worse than a corrected one.

PRC-15 stays open. The ownership manifest, its hook rule and the ownership sane check remain — though worktree isolation may make the manifest unnecessary, since its entire purpose was to referee a shared tree.
