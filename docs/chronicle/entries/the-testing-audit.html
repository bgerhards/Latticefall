An audit of the thing everything else rests on

PRC

An adversarial pass over all 29 gate checks, the 1,152-run parity matrix and the scenario harness. The finding that stung: the guarantee this project calls falsifiable has never once actually run in continuous integration.

Everything below is measured, not impressions.

The finding that stung: never once past tier 1

rules parity — the check CLAUDE.md itself names as the thing that makes a balance claim falsifiable — has run in CI exactly zero times. There are zero registered runners attached to the repository, the nightly workflow has zero runs in its own history, and the variable that would enable it is not set. Every gate failure recorded in this project's history was CI's own onboarding breaking itself, never a real defect caught in the act.

The gate's documentation had drifted from the gate

check.py's own docstring undercounts its tier-3 and tier-4 totals by one each, because neither mentions the scenario check that had since joined the gate. STATE.md's gate block, regenerated the same day, records 21 checks against an actual 29. A tier table nobody can trust is worse than none, because the entire argument for tiering rests on knowing exactly what a given tier excludes.

The coverage gaps and the matrix itself

No automated coverage exists at all for gamepad input, save and load, or the recovery draft — and no loudness measurement, despite loudness-matching being one of this project's own named non-negotiables. The two scenarios that assert something specific, the ability numbers and the worst accessibility case, were built and never wired into the gate; only the smoke test was. Separately, the parity matrix is not obviously right-sized: four of sixteen grading policies exercise one shared dispatch path across all 24 anchors — 288 of 1,152 runs, 25% of the total — for a claim that plausibly does not need per-anchor coverage at all.

Two results worth recording even though neither became an issue

Parity has real teeth, demonstrated rather than assumed: a one-sided change to BROWNOUT_SLOPE, made in the Python engine only, inside a disposable worktree, was caught with 30 differences on anchor-24 — and reported clean on anchor-01, because that anchor never pushes reactor capacity hard enough to exercise the constant at all. The flat run count hides that coverage is anchor-dependent; an anchor-01 spot check is not the same thing as coverage. And the checks read as less redundant than expected: sprite coverage against asset coverage, and the three rendered checks, were each read closely and found to compare genuinely different things. What redundancy exists here is structural, not check-against-check.
