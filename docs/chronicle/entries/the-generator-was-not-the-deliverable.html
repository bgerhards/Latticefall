LF-080 — THEATRE SCALE 05 — is the large-board layout generator, tools/genboard.py. Decision 073 set the board target to 48×48. Shipped anchors are 12–18 wide by 10–15 tall. Hand-authoring a four-lane 48² anchor with a converging funnel and 78 sited emplacement slots is not viable, so the generator had to exist before the content could.

Nothing in that block is a constant somebody typed

Every budget is a shipped-content ratio re-measured off data/anchors/ at run time, multiplied by a measured property of the generated board. Slot count is union lane tiles divided by 3.5. Capacity is slot count × max draw × 0.50. Funds come from the shipped funds-per-slot ratio, lives from the act's leak budget, wave mass from the lane-length ratio. Change the shipped content and the generator's output moves with it, which is the only way a generator stays honest as the game it scales from is tuned.

Validated clean — 0 schema errors, 0 check_anchor errors, 0 warnings — across nine configurations: lanes 2–5, sweeps 1–5, 32² / 48² / 64², acts 1–3. Deterministic: --selftest generates twice and compares byte-identical at 35,522 bytes; two --out runs diff empty at the same sha256; verified cwd-independent.

The prerequisite that was genuinely blocking, proved rather than described

LF-132: sim/content.py's all_anchor_ids() discovered anchors with a raw glob('anchor-*.json'), so any untracked file dropped in data/anchors/ was treated as real shipped content. The backlog entry had predicted, in as many words, that this would bite again the moment anyone built the large-board generator — because a generate, grade, discard workflow is exactly that.

It was proved by doing it rather than by reasoning about it. The generated board was dropped at data/anchors/anchor-25.json, untracked, and the numbers taken on both sides of the fix:

The gate check flipped which act it treats as the reference, and that is the part worth naming: not a crash, not a red run — a silently different answer to the question the check exists to ask. After the conversion the generated file is still sitting on disk and every number is back where it was.

load_anchor() was deliberately left alone, so an untracked board still grades by name — which is the whole generate-and-discard workflow, and the reason the fix belongs in discovery rather than in loading. Both synthetic anchors were deleted afterwards; 24 tracked.

The finding, which is worth more than the tool

LF-187 predicted that decision 074's range numbers would not survive 48²: longer lanes mean a fixed absolute range covers a shrinking fraction of the board. That is now measured rather than predicted.

With budgets derived from the geometry instead, the same board grades ok at all three. So the control does its job: it separates the range-and-budget question from the layout question, and the layout is not what is broken.

A second defect shows up in that same derived grade, and it belongs to BAL-04 rather than here: the winner set and the death wave do not move across difficulty at all. Four distinct builds at each of standard, hard and brutal; all three dying at wave 7; the same four policies winning every time — burst, greedy-overdraw, anti-armour, overcharge-greedy. Margin moves — winners finish on 106–126 lives at standard and 10–64 at brutal — but selection does not. Difficulty is changing how close it is, not what works.

LF-218 does not get structurally worse at 48², and that was worth checking rather than assuming. Cumulative presence reaches 25 / 50 / 75 / 90% at lane fraction 13 / 31 / 57 / 81% on the generated board, against 14 / 32 / 58 / 82% on anchor-20. The last quarter of the lane carries 13.6–14.1% per lane against anchor-20's 14.1%. The four lanes carry 26.9 / 23.8 / 25.3 / 23.9% of live unit-ticks, which is about as even as a four-lane board gets.

So the attrition profile is scale-invariant once slot count scales with lane length. What collapses is per-emplacement work, not the shape of the tail — which is precisely a range problem and not a layout one. That is the same 13 tiles, reached from a different direction.

The instrument fooled itself again, one entry after being repaired

verdict() printed “no material near-zero tail (6% of emplacements)” for a board whose own ceiling is 11.9%. The (0) branch short-circuits on the near-zero fraction before branch (b) ever consults board_presence_ceiling. Filed as LF-229.

It is invisible on all 24 shipped anchors, because their ceilings are 75–95% and the short-circuit gives the right answer every time at those levels. Only a board unlike any shipped board reaches the hole.

Worth saying plainly rather than filing quietly: entry 53 rewrote those exact labels earlier the same day, and the rewrite has a hole. It is the same lesson as firing arcs agree, and it keeps arriving in different clothes — a check that runs over all shipped content proves nothing about a branch the shipped content never enters.

What slots is still for, after PLC-04

Checked against the tree rather than assumed, because the generator has to decide how much care to spend siting slots that free placement has arguably made decorative. The answer is a clean three-way split:

  • The count is a real budget. _effective_cap() takes max_emplacements else len(slots), and it is the binding constraint in every run graded here — 12 of 16 policies fill all 78 and stop. It is also validate_data.py's saturation denominator and board_presence_ceiling's n_slots.
  • The positions are an instrument input and a validator input. validate_data.py's bounds, on-path, duplicate, dead-slot and ramp/cliff checks; all of sim/coverage.py's per-slot work; the editor overlay; PLC-06's autoplay fallback (LF-207); and _slot_priority(), kept alive solely for decision 022's measurement.
  • The positions are dead to both placement paths — the grader's (7,402 lattice candidates on 48² against 579 and 763 on shipped boards), the player's, and the board render.

So the generator sites slots carefully only because the coverage instrument reads them. A generator that emitted max_emplacements and no slots at all would grade identically and be unmeasurable — which is a good argument for keeping the field and a bad one for believing it still does what its name suggests.

Two more filed on the way through

  • LF-228 — anchor_view.gd::_on_built() computes the ward-engagement total as placed + available_slots(). With free placement that total grows with every build, so wards-full never fires; and on a slots-less anchor it equals placed, so wards-half and wards-full both fire on the first build.
  • LF-230 — InstrumentedSim's overhead is 2.1× at 12 emplacements and 6.8× at 78 (3.88 s → 26.41 s, same policy, Outcomes field-identical). A full coverage pass is 2.5 minutes on anchor-20 and 21 minutes on the 48² board; a 64² board derives 131 emplacements. The rules got WAR-03's spatial grid. The instrument did not.

Not a refusal, with one caveat worth recording

The sim cost does not explode at this scale. The candidate lattice builds in 125 ms, a plain run is 2.5–4.9 s, a full 60-cell grade about 7.5 minutes. Maximum sim_seconds observed was 1,397 against a MAX_SIM_SECONDS of 3,600 — so nothing is being killed by the clock. But that headroom is 2.6×, and a 64² board with slower act-3 units will approach it. Recorded now, while it is still comfortable.

And one thing that is not about scale at all: all 16 policies reach the emplacement cap during wave 1's 22-second lead-in — on the generated board and on shipped anchor-24. Nothing is sequenced after the first decision. That is inherited from the shipped funds-per-slot ratio rather than caused by the board size, which is exactly why it matters: scaling the ratio forward carries the defect forward with it.

What this entry does not have

The work sits on lf/ts-layout-generator and is uncommitted as this is written, so there are no commit hashes here. A tier-4 gate is in flight and no verdict is stated — the result belongs in the entry that actually has it, not in a hopeful sentence in this one.

Five entries, and the tool is the least of them

Five entries today. Four of them found the fault in an instrument — the metric, then the test of the metric, then the acceptance criterion, and then the four real defects those repaired instruments exposed. This one built a tool, ran the repaired instruments over its output, and got a number.

The tool is not the deliverable. The measurement the tool made possible is. Thirteen tiles is a whole balance epic's starting point, and it did not exist this morning.
