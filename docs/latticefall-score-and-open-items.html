00Method

Before you generate anything

Fourteen tracks, one sonic spine. The spine matters more than any single prompt — it's what stops the soundtrack sounding like fourteen unrelated pieces from fourteen different games.

Paste the Style block into Suno's style field and the Exclude block into its exclude-styles field. Every prompt already carries the spine, so you can generate them in any order, across sessions, and they'll still cohere. Turn Instrumental on for all fourteen — there are no vocals anywhere in this score.

Global sonic spine — present in every prompt below
Core palette
Detuned analog synth pads, low brass clusters, bowed metal and cymbal, prepared piano, sub-bass pulse, tape saturation and hiss.
Percussion
Absent in build phases. Combat uses dry military snare, low taiko, and metallic industrial hits — never electronic drum kits.
Harmony
Modal and static. Minor seconds and tritones for the Ordinal; open fifths for Meridian. Avoid functional chord progressions that resolve.
Tempo
Build 54–66 bpm. Combat 92–116 bpm. Nothing faster — this is a game of decisions, not reflexes.
Never
Epic orchestral trailer hits, choirs, dubstep, supersaw EDM leads, uplifting major-key resolutions.
Read this before spending credits → Suno writes linear tracks with intros and endings. Games need seamless loops. Ask for static, non-developmental pieces (every prompt below does), then I'll cut sample-accurate loop points with ffmpeg and export Ogg Vorbis for Godot. Budget roughly 3–4 generations per track to get one that loops cleanly. Also confirm your Suno plan grants commercial use before this ships — the free tier does not.
01Tracks

The fourteen

Naming convention is ACT-ROLE so files sort into playback order on disk. Build-phase and combat tracks within an act share tempo and key so the engine can crossfade between them at a wave boundary without a jarring transition.

02Delivery

What to send me

Download the best generation per track as WAV, not MP3 — I'll do the lossy encode once, at the end, rather than stacking two generations of compression artifacts. Name them by track ID and drop them in a folder.

audio/source/TTL-01_latticefall_main.wav
audio/source/A1-BLD_carrier_signal.wav
audio/source/A1-CMB_warden_protocol.wav
…

From there the pipeline is deterministic and scripted: loudness-normalize to −16 LUFS, detect and trim to a seamless loop point, encode to Ogg Vorbis q6, emit a .tres resource per track with loop_offset already set. You never touch Godot for any of it.

Not blocking → the whole audio layer sits behind a stub bus. The game builds, runs, and is fully verifiable with zero audio files present. Send tracks whenever; nothing waits on them.

③ Sound effects are not music

The score is fourteen tracks. Combat needs roughly sixty discrete effects — turret fire per tower type, impacts, deaths, the reactor hum, brownout alarm, UI clicks, gate ambience. Suno is the wrong tool for those.

Recommend — a curated CC0 bank from Freesound plus synthesized UI tones I generate with scripted DSP, so UI audio is reproducible and tuneable rather than a pile of downloads. Needs your yes before I build the bank.

Decided — display typeface

Proceeding — IBM Plex Mono and IBM Plex Sans Condensed, both SIL OFL, redistributable with the game. Technical without being a cyberpunk cliché, and the mono has the instrument-readout quality the UI wants.

Decided — target and platform

Proceeding — 1920×1080 design resolution, desktop first, mouse and keyboard. Gamepad support is architected for but not implemented until the campaign is content-complete.

Decided — difficulty

Proceeding — three modes driven entirely by data multipliers over the same wave tables, so the headless simulator can grade all three in one pass.

Decided — dialog presentation

Proceeding — animated portraits with typewriter text, no voice acting. Mid-wave lines never block input and are always skippable.
