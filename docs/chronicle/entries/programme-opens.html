I want a battle, I WANT A WAR

PRC

The owner played the build and asked for scale. The session opened with a backlog, a measured foundation, a PRD built on five pillars, and 74 issue specs decomposed across seven epics — reviewable in git before a single one became a GitHub issue.

Latticefall today is a competent tower defence with one genuinely good idea: power is the real currency. The largest board is 18x15 tiles, peak screen presence is 32 units, one lane, one entrance, one exit, and a fixed list of eight to twelve places you are allowed to build. The owner played it and said what they wanted next, in their own words:

I want a battle, I WANT A WAR.

Theatre Scale is the programme that turns a screen into a battlefield. It rests on five pillars: ground you cannot cover, build where you want (no fixed slots), terrain that means something (elevation and bridges), weapons you can see from across the valley (spectacle as different shapes of power draw, never just bigger numbers), and power as a front line — supply you build, route, and defend.

One rule outranks all five. The rules of the game exist twice — scripts/anchor_sim.gd for the engine, sim/engine.py as the reference — and a parity harness diffs them on every commit: 864 runs when this session opened, 1,152 by the time it closed. That is what makes any balance claim in this project falsifiable, and every entry after this one either keeps both implementations in step or says plainly that it does not.

The specs live in docs/issues/*.md and are the source of truth; GitHub is a projection built by tools/issues.py, so a lost repository or a rate limit costs nothing — re-run it and the issues come back identical. Twenty-two of the seventy-four could start with nothing blocking them.

The dependency graph was checked rather than trusted. tools/issues.py derives 'blocks' from 'depends', and the two had drifted: of thirteen hand-written 'blocks' claims, ten were either transitive or simply wrong — one asserted it blocked work the plan deliberately wanted running in parallel. Three were real, and became depends edges instead, which is the side that actually counts.

Four traps surfaced before a single issue was implemented, all found by reading the code the specs would touch rather than by writing the specs first and finding out later. The parity outcome signature encodes tower positions as %s@%d,%d in both engines, and free placement makes those floats — the grader's candidate positions would need pinning to a binary fraction to round-trip identically between languages. The parity test harness turned out to carry its own private copy of two build-placement functions, making the free-placement work a three-file change rather than two. Sprite yaw slots are named y%03d and the heading function returns a plain integer, and sixteen directions are 22.5 degrees apart — half of them not whole numbers — so that naming has to become bucket indices before a single new asset can render. And one rules file justifies a piece of bookkeeping 'because records are only ever compared by slot' — free placement removes the slot, so that invariant needs a new basis at the same moment it needs everything else.

Nothing above was built yet. It was the day the plan got measured instead of argued — which is also the subject of the entry that follows, and which happened, in fact, a little earlier the same evening.
