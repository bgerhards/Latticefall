Measured, not argued

CAMART

The numbers a performance change is judged by, taken as seriously as the parity run that proves it changed nothing else: a 2.65x speedup at 64x64, a quadratic draw cost flattened to a constant, a texture limit nobody on this machine had actually measured, and a dimming factor checked to within 8-bit quantisation.

'A change that passes verification has only proved it changed nothing observable, which is also what a no-op proves' is a rule this session earned the hard way (see the entry on this day's failures, later in this journal). The discipline it produced shows up everywhere a number gets quoted here: measured, never inferred.

2.65x, at the frame that does not exist yet

The board was drawn with no culling and no caching at all — 4,096 tile draws a frame at 64x64 before a single unit even moved — and the list of everything to draw was rebuilt and re-sorted four times a frame, once per draw layer. Tiles are now cached once per anchor and culled against the camera's visible rectangle; the draw list is built once and shared across all four layers. Measured at 64x64 with 60 emplacements and roughly 530 drawable objects: the board's own draw call goes from 11.13 ms to 4.57 ms, and the total across all four layers from 14.35 ms to 5.42 ms — a 2.65x speedup. On today's actual anchors the win is a smaller 1.44x, because the frame was already cheap there; the point of the work is the board that does not exist yet. Five deterministic no-combat frames came back byte-for-byte identical before and after, and so did a full-combat frame.

A quadratic term, bucketed flat

The hit-flash lookup scanned the entire live hit list for every drawn unit — climbing from 9.3 microseconds to 58.1 per call as a standalone benchmark's crowd grew from 150 to 900 units. Bucketing it by tile and searching only the surrounding neighbourhood holds per-call cost flat at 2.2 to 2.9 microseconds across that same range, proved against 910 differential queries with zero mismatches — including the exact tie-break the original scan preserved by walking ascending indices, which the bucketed version had to reproduce by comparing distance-and-index pairs regardless of which order its buckets happen to be walked in.

A number nobody on this machine had actually measured

GL_MAX_TEXTURE_SIZE was assumed rather than known, until an EGL surfaceless probe against the same software rendering stack the game itself uses returned 16384. The atlas packer's own asserted floor is 4096 — not the GLES 3.0 specification minimum of 2048, because 2048 would already fail the page this project renders today at 3072 px.
