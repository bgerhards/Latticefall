## Read this first, before running anything

**Godot capture is invisible now — `LF-061` is closed, not bounded.** On this WSL2 machine,
`tools/toolpaths.godot()` prefers a native Linux Godot build
(`/mnt/d/godot/linux/Godot_v4.7.1-stable_linux.x86_64`), and
`tools/toolpaths.godot_argv(..., want_window=False)` runs it under an `Xvfb` virtual
framebuffer via `xvfb-run` — a real, GPU-backed (Mesa llvmpipe software GL) window that no
compositor ever presents to a screen. That is the fix, not a mitigation: the old failure
mode was macOS throttling a window it considered occluded, stalling
`await RenderingServer.frame_post_draw` in `main.gd` until the window came back into view —
one `game renders` once took 36 minutes and still reported `ok`. With no desktop in the
loop, there is nothing to occlude. Decision 052.

**`tools/shot.py <anchor-id> --out PATH` is how you look at the game.** It wraps the
invisible launch, relays Godot's `SHOT`/`FRAME`/`STATE`/`AUDIO`/`FACE` lines, and fails
loudly on a blank frame or a PNG write error rather than reporting a false pass. `tools/
check.py`'s `game renders`, `menu renders` and `accessibility`, and `tools/test_parity.py`,
all go through the same `tools/toolpaths.godot_argv()` now. `tools/check.py --no-window`
still exists, but it is a **speed** option — skipping five extra Godot launches — not a
courtesy; nothing about the full gate disturbs anyone at the machine anymore.

A machine with no native Linux Godot build, or no `xvfb-run`, falls back to the old
Windows-exe/macOS-bundle resolution and a real, visible window — the previous caution about
asking before running the full gate still applies there.

**Kill what you start.** `tools/reap.py --kill` at every wrap, `tools/reap.py` at every
start. A session declared wrapped once left processes running for over thirty minutes and
billed the owner's paid credits — the cost is not the idle core, it is that a background
process the agent harness still tracks **re-invokes the model when it finally exits**, so a
forgotten child bills turns against a session everyone believed was over. Prefer the
foreground; never leave a monitor or poll loop armed.

**None of the new gameplay is balanced — only verified.** Speeds, the call-wave bonus, the
kill chain, the three abilities, targeting, veterancy and the recovery pool were all authored
into `data/tuning.json` with reasoning and then confirmed to *behave as specified*. Not one of
them has been graded, and they cannot be by the current harness: `sim/engine.py` never presses
a button, so the sweep and the grader are blind to every one of them. The 24 anchor grades in
the block below therefore describe a player who uses none of this. That is a floor, which is
the same argument decision 033 made for `sell()` — but the floor is now much further below
real play than it used to be, and **the abilities are the most likely thing in the game to be
accidentally overpowered**. A grading policy that can press a button is the missing piece.

**Two verification gaps are known and small.** Which candidate each targeting mode selects
from an identical pool is argued from the code, not proven from data; and overcharge's
fire-rate change is analytic plus measured bus load rather than a clean before/after shot
count. Both are cheap to close if either becomes load-bearing.

## The three act mechanics

- **Act I — power scarcity.** Brownout priced by overdraw size,
  `min(0.70, (load/cap-1)*1.5)`. Decision 022.
- **Act II — the bus is contested.** `drains_mw` units steal capacity while alive; the
  **anchor damper** suppresses 60% of the drain inside its arc. Decisions 027, 029.
- **Act III — the bus degrades.** `capacity_decay_mw` per wave, floored at 45% of rated;
  the **restorer** returns 44 MW for 10 MW drawn and a slot spent. Decision 031.

Across all three: **a leak costs the unit's `leak_cost`, not a flat life** (decision 047),
and **each act's escorts are budgeted against the resource that limits that act**
(decision 048).

## What the next task probably is

**A grading policy that can press a button.** This is the biggest hole and it opened this
session. Twenty-four anchors' worth of balance is graded against a player who never uses
speed, never calls a wave early, never fires an ability and never retargets — because
`sim/engine.py` cannot do any of those. Every grade in the block below is now a floor well
under real play, and the abilities in particular are the most plausible thing in the game to
be quietly overpowered. Related: `LF-053`, whose capped-core policies are a prerequisite for
expressing a mixed board at all.

**`LF-052`, the board camera — pan and zoom.** The item the owner asked for directly, before
the playtest redirected the work. Nothing has been written to any game file, so there is
nothing to unwind. The scoping already done, from reading the code rather than guessing:

- `anchor_view.gd` adds a manually computed `_origin` to every `tile_to_screen` result and
  picks the mouse with `screen_to_tile(get_global_mouse_position() - _origin)`. Its `position`
  is now used by the **screen-shake trauma system**, so a camera would have to compose with
  that rather than own the transform outright. Every board layer — `Backdrop`, `BoardProps`,
  `CombatFx`, `GlowLayer`, `FxAdditive` — is a *child*, so they inherit for free.
  **But `Backdrop` sizes itself to the raw viewport independently of the board**, so scaling
  the parent would tear it; that is why `_centre()` is translation-only today and why zoom
  needs `backdrop.gd` looked at first.
- The HUD is a `CanvasLayer`, so it is untouched by a board transform — which is what makes
  "zoom the board only" cheap, and it must stay that way: the ladder and palette were solved
  for WCAG AA at a known size (045/046/050) and scaling them with the board silently undoes it.
- Clamp zoom at 1.0. Past it the sprites soften, because they are a fixed 256 px atlas at one
  orthographic scale; raising the render base means re-rendering 224 sprites for a feature
  whose value is inspection.
- Pan on middle-drag and the `lf_*` action map, **never** left-drag — left click arms builds
  and selects emplacements, so drag-to-pan turns every slipped click into a camera move.
- anchor-24's board is `(18+15) * 64 = 2112` px wide — **wider than the 1920 logical viewport
  at 100%**, not equal to it as this file previously claimed. It cannot fit even the raw
  viewport, let alone the strip between the instrument panels. The viewport also *shrinks* as
  interface scale rises (960x540 at 200%), so zoom-out has real value and partly relieves
  `LF-057`.
- It needs a `--camera x,y,zoom` verification hook, or every `--shot`/`--a11y` report becomes
  camera-state dependent.

## Traps that have already cost time

Full detail in `CLAUDE.md` and in the decision entries.

- **Density must never be paid for with reactor capacity.** The heavier tables grade clean
  if the bus is allowed to grow, and the sweep will buy exactly that: anchor-24 reached
  **103% of what would run every slot at maximum draw**. Every anchor still graded clean,
  and the power decision the whole game is about had stopped existing on five levels. The
  grader cannot see this — a level with no decision in it is still winnable. Capacity is now
  bounded at 70% of board saturation in the sweep grid, and `validate_data.py` errors at
  saturation and warns from 80%.
- **A transform that is free to cut the wave table will destroy it.** At a tight allowance,
  251 of 252 Act III spawn entries came out at `count: 1` — every wave of the last three
  anchors reduced to "N shards and one of each". Undershooting a density target is a tuning
  miss; flattening composition is a content loss, and they are not the same severity.
- **A derived quantity that another term compensates for does not announce itself.**
  `solve_scale`'s denominator was algebraically wrong for six revisions; the escort residual
  absorbed the error, so the tables looked plausible while the target was missed by a fifth
  on every Act III anchor. Re-derive from the docstring, do not read the code.
- **The briefs speak their own numbers.** Control reads the bus figure aloud in every anchor,
  and `sweep.py --apply` moves `capacity_mw` without touching a word of prose. Sixteen briefs
  had drifted. `tools/say_capacity.py` reconciles them and the gate now checks it.
- **The gate's rendered checks used to read the player's save.** `window_mode`, `resolution`
  and `ui_scale` live in `user://progress.json`, outside the repo, so the same tree reported
  coverage 0.56 and 0.34 on two machines. Every rendered check now leads with
  `--display-defaults`, and it must come *first* because it resets `ui_scale`.
- **The gate scans the backlog.** A backlog item that quotes a banned term turns the
  nomenclature check red. Describe the hits; never repeat them.
- **`check_banned_terms` rglobs the whole repo**, so an agent worktree under `.claude/`
  carrying its own copy of the nomenclature bible failed the gate with six false hits.
  `.claude` is skipped alongside `.venv`, `addons` and `.godot`.
- **Backlog ids collide across worktrees.** The stored `next_id` counter cannot see items a
  merge brought in; it minted a second `LF-055`. It is now
  `max(counter, highest id present + 1)`.
- **Killing `check.py` does not kill its headless Godot.** It reparents to init and holds a
  core at 100%. `tools/reap.py --kill` is now the answer; do not rely on remembering `ps`.
- **An occluded Godot window stalls the check that opened it, and the check then passes.**
  36 minutes, reported `ok`, on a real desktop window. `LF-061`, decision 051. Closed by
  decision 052 on this machine — Godot capture now runs invisibly under `Xvfb`, so there is
  no window to occlude — but the trap is still real on a machine with no native Linux Godot
  build or no `xvfb-run`, which falls back to the old visible-window path.
- **A GDScript parse error is a HANG or a blank frame, never an error at the failure site.**
  `var x := node.method()` where the receiver is an untyped var or a bare `Node2D` cannot be
  inferred, and that is a *parse* failure, so the whole script fails to load. Godot then
  downgrades the node to a scriptless base class and the cascading errors name files that are
  **not broken**. This cost time five separate times in one session, in five different files;
  once `main.gd` failed to parse and the game simply hung on the menu with no output at all.
  Annotate anything reached through an untyped reference. `--headless --path . --check-only
  --script res://scripts/<f>.gd` checks one file in seconds (it reports spurious "Identifier
  not found" for autoloads — those are not real).
- **Rebuilding `.godot/` blanks the level for whoever is playing.** The owner plays out of the
  same working tree agents edit. Moving the folder aside to force a cold import pulls every
  imported texture out from under them: the menu still draws, the level comes up blank, and it
  reads exactly like a code regression. It was diagnosed as one for a full pass. Import in
  place, and say so first. An import by the Linux build also does not satisfy the Windows
  editor, which re-imports on open. `LF-075`.
- **A subagent with no `model:` key inherits Opus.** All five carried none. The `agent models`
  gate check exists so this cannot come back quietly.
- **`awk`'s record counter persists ACROSS files.** `awk '/^---$/{n++} n==1' .claude/agents/*.md`
  inspects only the first file and reports 1 however the rest are set. Needs `FNR==1{n=0}`.
  The same shape of error as any check that passes for the wrong reason.
- **Python block-buffers a redirected stdout**, so `check.py | tail` or `| tee` shows nothing
  until the run ends — a stalled gate is then indistinguishable from a slow one. Use
  `python -u` when the output is going anywhere but a terminal.
- **`sprite atlas` does not launch Godot.** Only `game renders`, `menu renders` and
  `accessibility` do. Verified by parsing the call sites; guessing from the names got it wrong.
- **Godot's `Vector2` is float32 and `distance_to` is not correctly rounded.** The rules use
  `PackedFloat64Array` and squared range tests.
- **A new `class_name` is invisible until the editor imports, and the symptom is a hang.**
- **A theme override under a name the theme does not know is accepted in silence.**
- **`Label.clip_text` clips horizontally only.** A zero-height label still draws a line.
- **An art fix can look like it did nothing in two ways** — a skipped `--import` serves the
  cached `.ctex`, a stale atlas serves the old pixels. render → `mask_glow` → `pack_atlas`
  → `--import` → screenshot.
- Colours are authored in **sRGB** and linearised by `mat()`; the sprite pivot is
  **measured** by `calibrate()`; ffmpeg here has no libvorbis; do not tune the music loop
  splicer against a seam metric (decision 011).
