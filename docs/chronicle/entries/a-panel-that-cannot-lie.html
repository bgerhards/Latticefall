Two changes landed in one pull request because they are the same subject — how the unattended loop runs — not because unrelated work got batched: a web control panel for the loop, and decision 077, which moves that loop's model.

The lever within reach was Ctrl-C

--status and --stop, from the two entries earlier today, answer the right questions — but only from the terminal the loop was started from. The owner was not there: they started a night run, saw something they disliked, and Ctrl-C was the only lever within reach. tools/autoloop_web.py is one stdlib HTTP server and one self-contained page at localhost:8732 — state, a live session log, and three buttons: Stop after this issue, Kill now, Start.

It invents no state of its own. It renders .cache/autoloop.lock, .cache/autoloop-status.json and the newest session log — the same files --status reads — so the page cannot disagree with the CLI, and every button reuses the CLI's own mechanism: the stopfile, two SIGINTs, spawning only after preflight passes. Two design points worth naming. Preflight now runs in the server *before* it spawns, so a refusal reaches the page instead of dying four seconds later in a log nobody opened. And a stale lockfile — what a kill -9 leaves behind — reports as STALE LOCK rather than “running”, because a panel telling the owner a dead loop is alive is the one lie that would cost them a night.

Nearly the second known leak

tools/audio/serve.py is named in reap.py's own docstring as a leak, because serve_forever() has no exit condition at all, and on this project a forgotten background process is a money bug, not housekeeping. The panel holds a lease and shuts itself down after --idle seconds with no request — the page polls every 2 s, so no requests means no browser has it open, which is exactly when it should stop. Verified live rather than assumed: it printed no request in 60s — shutting down, released its lease, and reap.py reported clean.

The obvious fix to that leak was considered and rejected

Adding the panel — and autoloop.py itself — to reap.py's OUR_TOOLS looked like the tidy move and was wrong twice over. reap.py --kill runs from the SessionEnd hook, so an overnight loop would be killed by an unrelated session ending somewhere else entirely. And autoloop.py's own preflight refuses to start unless the reaper reports clean — it would see the loop, then the panel, and refuse to start either. An unattended loop that runs all night is not a stray process; the reasoning lives in the module's own docstring, not only here.

  • Page loads 200, /api/state correct against both a running and a stopped loop.
  • Stop from the page is graceful — the loop logs SIGINT — will stop after the current issue finishes, ships its issue, exits 0.
  • Kill and Start both refuse correctly with no loop running and on a dirty tree.
  • An unknown route returns 404.

Decision 077 — the main line runs on Opus

At the owner's instruction: autoloop.py --model now defaults to opus, and all six subagent definitions in .claude/agents/ are repinned from sonnet. This supersedes only the model half of decision 051 — its reaper and bounded-subprocess halves are untouched.

The insight worth keeping is what re-reading 051 turned up: the invariant it actually bought was that every agent *states* its model, not that every agent is cheap. All five agents 051 addressed had carried no model: key at all and silently inherited Opus, which is what had spilled the owner's subscription into paid credits in the first place. Read that way, the gate check (agent models) survives 077 intact and becomes *more* load-bearing, not less — with an expensive model chosen deliberately, drift off the pin is what would quietly change the bill. The value now lives in one constant, AGENT_MODEL, rather than a literal comparison.

The corollary inverts guidance this file has carried for a while: a five-way fan-out used to be the cheap move and no longer is. CLAUDE.md now says to dispatch the agent the work needs, not a panel of them.

A count that had already rotted, in the file that warns about it

CLAUDE.md's own verification line for the agent pin said “→ 5” while six agent definitions already existed — a number written into prose, in the same file that names that exact failure mode and tells the reader not to trust a count without a check behind it. It now names the live count instead of a fixed one.

Said plainly, because the house style is not to round it up

Three consecutive pull requests have now been infrastructure — the loop's notifier and stop path, the Ctrl-C process-group fix, and this one — on a project whose standing orders default to game-facing work. None of the three were optional: an unattended loop that cannot be stopped safely or seen from another room is not one that should have been left running. This panel is meant to be the last piece of scaffolding before the loop is pointed back at real backlog issues rather than at itself.
